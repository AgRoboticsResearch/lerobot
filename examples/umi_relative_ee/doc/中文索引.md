### `live_inference_input_contract_and_pose_source.md` — P0，当前有效

- **核心结论**：
  1. π0.5 推理输入是 **1 张图 + task token**；20D state 被离散化后塞进 PaliGemma prompt，不是单独张量。
  2. 时序信息在 20D state 的 `[prev, current]` 里，不在图像历史；多图槽位是**空间相机**，不是 `t-1`。
  3. 不要求显式 previous pose：单帧 `[B,7]` 时 processor 会用 `prev = current`。
  4. 规范 UMI 部署时用机器人 FK 的 TCP 位姿，**不在线跑 SLAM**；SLAM 只用于离线数据采集。
  5. 磁盘上的 "absolute" action 是 **SLAM 相机轨迹在 episode 起点跟踪系**下的位姿（§6），不是机器人基座系 EE；部署时是 Piper FK 的 `camera_link`。模型只消费相对量，所以两者能通用。
- **仍然有效**：以上输入契约、state 构造、sync/async 的 `[prev,current]` 差异。
- **注意**：文档写于 2026-08-04；当前 `deploy_umi_relative_ee_piper.py` 已加入 USB 相机和夹爪重标定，但这些不改变本文的位姿/state 契约。
- **对应代码**：`src/lerobot/processor/umi_relative_ee_processor.py:296-341`；`src/lerobot/policies/pi05/modeling_pi05.py:1227-1242`；`src/lerobot/policies/pi05/processor_pi05.py:66-94`。
- **建议读法**：全文；重点 §1、§3、§5、§6。

### `rotation_normalization.md` — P0，分析有效、A/B 未完全闭环

- **核心假设 H1**：相对动作的 rot6d 在 identity `[1,0,0,0,1,0]` 附近聚集；per-dim MIN_MAX/QUANTILES 把很窄的对角线维度拉伸到 `[-1,1]`，在 loss 里给它们最大权重 `1/(q99-q01)`，反而让真正编码旋转方向 off-diagonal 维欠拟合 → 旋转抖动。
- **修复**：把 action 的 rot6d slice `[3:9]`、state 的 `[3:9]` 与 `[13:19]` 强制 identity stats；对应 `--policy.umi_rot6d_identity_norm=true`。
- **结论边界**：这是**假设 + 正在跑的 A/B**；文档明确说 π0.5 的 QUANTILES 本身没错，错的是把 6D 旋转喂给 per-dim 归一化；换 MEAN_STD 不解决。
- **已验证的部分**：stats distortion（`measure_rot6d_normalization_distortion.py`）确认 1302 数据上对角线维 q99-q01 ≈ 0.06–0.07，off-diagonal ≈ 0.35–0.49。
- **未闭环**：Phase 2 confirmation 仍标记 pending；`val/loss` 在不同归一化 arm 间不可比。
- **对应代码**：`src/lerobot/datasets/umi_relative_ee_stats.py:51-95`（`_force_identity_rot6d_stats`）。
- **建议读法**：TL;DR + "The divergence" + "Why per-dim scaling can hurt" + "Experiment"。

- **当前推荐**（§24、§28、README）：

  - 24GB 卡全参数微调在 Adam state 分配时失败；需要 80GB 级。
- **过时/历史部分**：§3 的 1000onesb 是早期数据集；§21 的 broad LoRA 和 §26 的全参数试验是历史路线；当前主推 §24/§28。

### `within_chunk_jitter_analysis.md` — P2，部分已被取代

- **核心结论**：
  - SmolVLA 的 chunk 内抖动是真实的，不是可视化/后处理造成的；但也不是 flow matching 的不可避免噪声底。
  - 审计发现 32D padding 的噪声/损失不一致会扰动 10 个真实维；但后续 A/B 显示 masked vs full-width 最终基本打平。
  - zero-noise 解码能把旋转加速度代理从 ~1.9° 降到 ~0.085°，但这是诊断，不是部署方案。
  - ACT 在同一时期约 0.04°，SmolVLA ~1.9°，π0.5 ~0.11°（25 个验证样本的 spot check）。
- **已被取代/历史**：
  - 文档顶部明确说 masked-inference 实验是 historical；当前 SmolVLA/π0.5 使用 OpenPI full-width 契约。
  - 旧的 `masked_subspace` 运行时不再是默认。
- **仍然有效**：指标定义（二阶差分不是真 jerk）、Gaussian 采样是主要抖动源、zero-noise 的定位、RTC 不能解决 chunk 内抖动。
- **建议读法**：TL;DR + "Metric terminology and limitations" + "Latest matched comparison"；后面的 masked 细节只看结论。

### `chunk_start_offset_transient.md` — P2，当前有效

- **核心结论**：A/B 视频里 ~300K 出现的固定 "向左移" 是输入无关的模型伪影；A（full-width）和 B（masked）**同时、同幅度**出现，所以不是 masked-subspace bug；它是训练动力学瞬态，400–600K 自愈。
- **实用建议**：部署/可视化优先用 ≥400K 或 100–200K 的 checkpoint；不要用 ~300K 的。

## 3. 数字口径（很重要）

这些文档里的数字经常被混着引用，至少分成四类：

| 指标 | 含义 | 典型位置 | 注意 |
|---|---|---|---|
| `val/loss` | 归一化空间里的训练/验证损失 | ACT: L1+KLD；SmolVLA/π0.5: flow loss | **不同归一化方案、不同策略、不同数据集之间不可比** |
| `rotation_end_deg` | chunk 末端（30 步后）的旋转误差 | `eval_open_loop_dataset.py` | 是精度，不是平滑度 |
| `rotation_chunk_mean_deg` | chunk 内各步旋转误差均值 | 同上 | 比 endpoint 更全面，但仍不是平滑度 |
| `rot_jerk_deg` | chunk 内旋转**二阶差分**代理（文档旧名 "jerk"） | 同上 | 不是真 jerk，也不是 endpoint；GT 也有值 |
| `xyz_end_m` / `xyz_jerk_m` | 平移端点和二阶差分代理 | 同上 | 单位分别是米、米/步² |
| `gripper_end` | 夹爪末端误差（归一化 0–1） | 同上 | 数据集约定 1=张开、0=闭合 |

常见混淆的出处：

- **0.0338 / 0.0332**：`README.md` 的 ACT **1459_occlusion** 1M run，是 **val/loss**，不是 endpoint，也不是本机 1302 run。
- **0.041°**：`within_chunk_jitter_analysis.md` 的 ACT @400K **1302 identity**，是 **rot_jerk_deg**，25 个验证样本。
- **5.82°**：同一张表的 ACT **rotation endpoint**；SmolVLA 在同表是 4.42°，所以"更平滑"不等于"更准"。
- **0.0432**：本机 `umi_unified_ee_action_chunk30_sroi_v2_masked_1302occlusiontrain_100val` 的 **val/loss @1M**（per-dim 归一化），和 0.0338 不同数据集/不同 arm。
- **0.077°**：本机 `act_umi_chunk30_onesb_v2` @510K 在 `val_v2` 上的 **rot_jerk_deg**；endpoint 是 4.96° / 2.03 cm。

比较规则：**同数据集、同验证 split、同归一化方案、同 checkpoint step**，否则只能看趋势，不能排名。

## 6. 一页结论

- **数据契约**：磁盘 7D 绝对（SLAM 跟踪系）→ 模型 10D 相对 rot6d + 20D state；chunk 内所有目标共用一个 base pose。
- **当前最稳的训练配方**：ACT identity rot6d（速度/平滑度好）；π0.5 38M split-rank LoRA（当前推荐）；SmolVLA full-width flow（与 masked 基本打平）。
- **当前最稳的部署路径**：同步 `deploy_umi_relative_ee_piper.py` 或异步 server/client；RTC 只对 π0.5/SmolVLA，且自定义 deploy loop 没接。
- **最大的未闭环问题**：rotation jumpiness 的 identity 归一化 A/B（Phase 2 pending）；chunk 边界/跟踪滞后的插值补偿（设计稿，未部署）。
- **文档使用原则**：把命令/路径/数值当可验证线索，把叙述性结论当"当时的假设"；先看状态标记，再看内容。
